# 정보 구조와 구현 결정

## 학습 경로

오늘 → 짧은 글 → 핵심 시각화 → 기억할 다섯 가지 → 개념 질문 → 다음 복습일 → 관련 지식으로 연결합니다. 사용자 활동이 없을 때 가짜 연속일이나 진척도를 표시하지 않습니다.

## 페이지 계층

- `/`: 네 영역의 일일 추천, 이어 읽기, 예정 복습, 무작위 글, 분야, 최근 기록
- `/explore/`: 상위 그룹 → 분야 → 하위 분류 → 기사
- `/topic/[id]/`: 영구 주소를 가진 정적 기사
- `/timeline/`: 공통 시간축으로 지역별 구간을 비교
- `/map/`: 중심 기사와 관계 설명의 제한된 이웃 지도; `?focus=id` 지원
- `/review/`: 복습 세션, 예약 목록, 상태, 이력, 백업

모든 경로 앞에 빌드 시 basePath `/knowledge`가 적용됩니다. 경로 변환은 Next Link와 `assetPath` 한 곳에서 처리합니다.

## 데이터 경계

MDX 본문과 전체 메타데이터는 빌드 시 읽습니다. 공통 메뉴와 탐색에는 `TopicSummary`만 전달합니다. 복습은 글마다 생성된 `public/data/topics/<id>.json`을 요청합니다. 새로운 글을 추가하면 정적 경로, 검색·탐색 목록, 복습 자료가 빌드에서 함께 생성됩니다.

저장된 개인 학습 데이터는 정적 콘텐츠와 분리됩니다. ID를 키로 참조하기 때문에 제목이나 문장 수정이 기록을 깨뜨리지 않습니다. 콘텐츠를 삭제해도 가져온 백업의 미지 ID를 강제로 버리지 않아, 다시 추가했을 때 기록을 보존할 수 있습니다.

## 복습과 동기화 경계

`learning.ts`는 순수 함수이고 `ProgressRepository`는 저장 어댑터입니다. 현재 localStorage 구현은 다른 탭의 storage 이벤트를 구독합니다. 동일 순간의 다중 탭 쓰기는 마지막 저장이 우선하며 서버 수준의 병합을 제공하지 않습니다. 향후 동기화 시 개별 이벤트 ID와 수정 시각, 충돌 정책을 별도로 추가해야 합니다.

저장 실패는 화면에서 알려주며 메모리 상태를 유지해 백업할 수 있게 합니다. 손상된 저장 데이터에는 자동 저장을 하지 않습니다. 복원은 형식 검사 후 사용자가 기록 교체를 선택했을 때만 수행합니다.

## 시각적 구조

따뜻한 바탕, 한국어 명조 제목, 산세리프 본문, 얇은 구분선과 절제된 분야색을 사용합니다. 오늘은 편집된 목차, 기사는 읽기 폭이 제한된 문서, 지도는 관계 주석 중심의 이웃 구조입니다. 세 화면을 동일한 카드 레이아웃으로 통일하지 않습니다.

## 확장 기준

현재 검색은 경량 메타데이터의 선형 검색입니다. 수천 개의 짧은 항목에서도 네트워크 검색 없이 동작하지만 규모가 커지면 정적 토큰 색인과 Web Worker로 전환할 수 있습니다. 본문 검색을 추가할 때는 공통 번들에 전체 본문을 넣지 말고 빌드 시 별도 색인을 생성합니다.

현재의 세계사 구간은 큐레이션된 개략 모델입니다. 수천 이벤트를 표시할 때도 먼저 기간·지역·중요도 필터로 수를 제한한 뒤 렌더링해야 합니다. 거대한 force graph로 전환하는 것은 학습 목표와 맞지 않습니다.

## 배포와 품질 경계

GitHub Pages에는 정적 파일만 배포합니다. GitHub Actions는 단위 테스트, 콘텐츠 검증, TypeScript/Next 빌드, Chromium E2E, axe 검사를 통과한 `out/`만 업로드합니다. 실제 GitHub 배포 실행에는 저장소 접근과 Pages 설정이 필요합니다. 로컬 테스트의 성공은 원격 배포가 수행되었다는 뜻이 아닙니다.

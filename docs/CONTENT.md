# 콘텐츠 작성 규약

한 글의 목적은 독자가 5~10분 안에 개념의 구조를 다시 그릴 수 있게 하는 것입니다. 개념을 암기해야 할 사실 목록으로만 만들지 않습니다.

## Frontmatter

모든 글은 `lib/schema.ts`의 `Topic`을 따릅니다. JSON 형태도 유효한 YAML이므로 현재 기사는 JSON을 `---` 사이에 넣습니다. 일반 YAML로 써도 YAML 파서가 읽습니다.

| 필드                     | 의미                                                      |
| ------------------------ | --------------------------------------------------------- |
| `id`                     | 영구 주소이자 학습 기록 키. 파일명과 같은 영문 kebab-case |
| `title`, `englishTitle`  | 자연스러운 한국어 제목과 영문 이름                        |
| `subtitle`               | 시대·저작·핵심 맥락                                       |
| `subject`, `subcategory` | `subjects.ts`에 존재하는 ID와 한국어 하위 분류            |
| `period`                 | 고대 / 근세 / 근현대 / 시대 없음                          |
| `kind`                   | 사람 / 개념 / 사건                                        |
| `estimatedReadingTime`   | 그림 조작과 복습까지 포함한 분 단위 예상 시간             |
| `difficulty`             | 기초 / 심화                                               |
| `prerequisites`          | 먼저 읽으면 좋은, 이미 존재하는 기사 ID                   |
| `relatedTopics`          | 기사 하단에 노출할 기존 기사 ID                           |
| `keywords`               | 한국어·영어 별칭, 역사적 명칭, 검색 의도                  |
| `summary`                | 핵심 모델을 담는 한 문장                                  |
| `overview`               | 3~5문장의 한눈에 보기                                     |
| `whyItMatters`           | 다른 지식이나 현대의 문제와 연결되는 이유                 |
| `takeaways`              | 정확히 5개의 독립적인 핵심 요점                           |
| `timelineEvents`         | `{year, label}`. BCE는 음수, 사건 없으면 빈 배열          |
| `reviewQuestions`        | 3~5개의 `{prompt, options, answer, explanation}`          |
| `sources`                | 검증할 수 있는 자료의 제목과 HTTPS URL                    |
| `visual`                 | 대표 시각화 레지스트리의 종류                             |
| `updatedAt`              | 내용 검토 날짜 `YYYY-MM-DD`                               |

`answer`는 0부터 시작하는 정답 선택지 번호입니다. 오답도 독자가 실제로 가질 법한 오해로 작성합니다. 질문의 해설은 정답을 다시 말하기보다 왜 그 설명이 성립하는지 알려주세요.

## 본문

대표 시각화·한눈에 보기·왜 알아야 할까·기억할 5가지·연결·질문·복습 컨트롤은 페이지 템플릿이 생성합니다. 본문 MDX에는 배경·직관·핵심 논증을 `##` 단위로 작성합니다. 같은 내용을 중복 생성하지 않습니다.

권장 순서:

1. 일상적 질문 또는 역사적 상황
2. 설명에 필요한 구분
3. 그림 또는 조작으로 핵심 관계 확인
4. 정확한 용어와 수식
5. 적용 범위, 반례, 흔한 오해

예를 들어 엔트로피는 ‘무질서’ 한 단어로 끝내지 않고 미시상태와 거시상태, 계의 경계, 통계적 경향을 구분합니다. 역사는 날짜뿐 아니라 누가 어떤 제약에서 선택했는지 설명합니다. 철학은 인물 간 선보다 주장과 반론의 관계를 드러냅니다.

## 연결

`relatedTopics`는 기사에서 이어 읽을 목록입니다. `relationships.ts`는 지도에서 사용하는 방향 있는 관계입니다. 관계는 서로 다른 역할을 하므로 둘 다 검토해야 합니다.

```ts
{ from: 'probability', to: 'entropy',
  type: '도구',
  label: '가능한 미시상태의 수로 거시적 경향 설명' }
```

관계 종류는 배경·확장·대조·도구입니다. 직접적인 역사적 영향이 아닌 비교 관계를 영향으로 표현하지 마세요. 링크할 기사가 아직 없다면 존재하지 않는 ID를 만들지 말고 본문에서 일반 텍스트로 다룹니다. 빌드가 잘못된 참조를 거부합니다.

## 연대와 출처

BCE는 음수로 기록하지만 ‘0년’이라는 역사적 연도는 없습니다. 광역 연대표의 좌표는 정수 연도를 쓰는 개략 모델이며 축의 0 위치를 서기 1로 표시합니다. 정밀한 일·월 단위 연대 계산용으로 사용하지 않습니다.

전통적 건국 연도, 고고학적 형성 시기, 국가의 공식 선포, 실제 지배 범위를 구분하세요. 문명권을 묶은 구간은 단일 국가처럼 보이지 않도록 설명을 붙입니다. 최신 국경이나 정세를 다루려면 기준일과 확인한 자료를 함께 기록합니다.

과학적 모형에는 가정과 생략한 요인을 표시합니다. 서적·교육 자료에서 도판이나 긴 문장을 그대로 복사하지 않습니다. 독자적인 설명을 작성하고 원자료 링크를 제공합니다.

## 게시 전

`npm run validate`와 `npm run build`를 실행한 뒤 기사 URL을 직접 열고, 모바일에서 그림·수식·질문을 확인합니다. 내용과 자료의 일치 여부는 작성자가 검토해야 하며 자동 검증만으로 사실성이 보장되지 않습니다.
